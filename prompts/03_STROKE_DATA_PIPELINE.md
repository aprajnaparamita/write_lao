# Prompt 03 — Stroke Data Authoring Pipeline & SVG Parser

## Context

You are building "Write Lao". Stroke matching engine is implemented (Prompt 02). Read `00_OVERVIEW.md` for architecture. This prompt creates the tooling to convert hand-drawn SVG stroke paths into the JSON format the app consumes.

## The Problem

Stroke data must be hand-authored. Each of the 58 Lao characters needs carefully drawn center-line strokes in the correct order. The workflow is:

1. Open the SVG template (generated by `make_svgs.rb`) in Inkscape
2. Lock the reference layer, draw strokes in the `strokes` layer
3. Run the converter tool to extract stroke paths into JSON

The existing example SVG (`01_01_ko_U0E81.svg`) has a hand-drawn path, but it has problems:
- The path is outside the `<g id="strokes">` group (it's a root-level element)
- It's a single continuous path for what should be 2 separate strokes
- It contains raw freehand Bezier data with too many control points and noise

This prompt creates a tool that can handle both clean and messy SVG input and produce usable stroke data.

## Goal

Build a Dart CLI tool (`tool/svg_to_json.dart`) that parses SVG files and outputs stroke JSON. Also create `lib/utils/svg_parser.dart` for the core parsing logic (reusable in the app if needed).

## Tasks

### 1. SVG Path Parser (`lib/utils/svg_parser.dart`)

Parse SVG path `d` attributes into point lists. Support these SVG path commands:
- `M` / `m` — moveto (absolute/relative)
- `L` / `l` — lineto
- `C` / `c` — cubic Bezier
- `S` / `s` — smooth cubic Bezier
- `Q` / `q` — quadratic Bezier
- `Z` / `z` — closepath

```dart
class SvgPathParser {
  /// Parse an SVG path d-attribute string into a list of points.
  /// Bezier curves are sampled at the given resolution (points per curve segment).
  /// Returns: List of point lists, one per sub-path (split at M commands).
  List<List<Point<double>>> parse(String pathData, {int curveResolution = 20});

  /// Parse a single SVG file and extract stroke paths.
  /// Looks for paths inside <g id="strokes">, falls back to any <path> elements.
  /// Returns: List of point lists in document order (one per <path> element).
  List<List<Point<double>>> parseFile(String svgContent);

  /// Extract metadata from SVG data attributes.
  Map<String, String> extractMetadata(String svgContent);
}
```

### 2. SVG to JSON Converter Tool (`tool/svg_to_json.dart`)

CLI tool that processes SVG files:

```bash
# Convert a single SVG
dart run tool/svg_to_json.dart input.svg -o output.json

# Convert a directory of SVGs
dart run tool/svg_to_json.dart ./lao_svgs/ -o assets/stroke_data/

# Options:
#   --resample N     Resample to N points per stroke (default: 48)
#   --canvas-size N  Reference canvas size (default: 512)
#   --min-length N   Minimum stroke length in px to include (default: 20)
#   --verbose        Print details about each stroke found
```

**Conversion logic:**

1. Read SVG file
2. Extract metadata from `data-lao-*` attributes on the root `<svg>` element
3. Find all `<path>` elements inside `<g id="strokes">`. If none found, find all `<path>` elements anywhere (excluding those in `<g id="background">`, `<g id="reference">`, `<g id="label">`).
4. For each path:
   a. Parse the `d` attribute into raw points
   b. If path has multiple sub-paths (multiple M commands), split into separate strokes
   c. Filter out strokes shorter than `--min-length`
   d. Resample each stroke to N evenly-spaced points
   e. Compute start angle and direction hint
5. Output JSON in the format from `00_OVERVIEW.md`

## Notes on SVG Path Parsing

The SVG path `d` attribute in the example file uses relative `m` and `c` commands with lots of decimal precision. The parser needs to handle:
- Both absolute (M, C, L) and relative (m, c, l) commands
- Comma and space separators between coordinates
- Implicit lineto after moveto (SVG spec: coordinates after M are implicit L)
- Negative numbers as separators (e.g., `100-50` means `100, -50`)

Consider using the `path_parsing` package from pub.dev if writing a full SVG path parser from scratch is too much scope. But verify it handles all the edge cases above.
